# Соответствие AMDB алгебре многомерных матриц Н.П. Соколова

**Аудит реализации против теории. Версия 1.0 · 27.08.2026**

Документ отвечает на вопрос: в какой мере реализованный программный комплекс
является алгебраической машиной баз данных *в смысле Соколова*, а не просто
программой, использующей `einsum`.

Проверка ведётся не рассуждением, а исполняемыми тестами:
[`tests/test_sokolov_algebra.py`](../tests/test_sokolov_algebra.py), 46 тестов.

```bash
python -m pytest tests/test_sokolov_algebra.py -v
```

---

## 0. Краткий вердикт

| Уровень | Что проверяется | Вердикт |
|---|---|---|
| **I. Операция** | Является ли реализованная операция (λ, μ)-свёрнутым произведением | **Полное соответствие**, подтверждено 30 тестами |
| **II. Алгебра** | Реализована ли алгебра как система операций | **Частичное**: реализовано ядро (произведение, сложение, транспонирование, внутренняя свёртка, единица); не реализована теория квадратных матриц (определитель, обращение) |
| **III. Машина БД** | Является ли исполнение запроса композицией операций алгебры | **Соответствие для линейных агрегатов**, подтверждено численно; для MIN/MAX — соответствие через обобщение на полукольца; вне алгебры остаются `COUNT DISTINCT`, `ORDER BY`, `LIMIT`, `HAVING` |

Главный содержательный вывод: **вычислительное ядро соответствует теории строго**,
и это проверяемо. Расхождения лежат не в ядре, а на периферии — в тех частях
СУБД, которые к алгебре многомерных матриц отношения и не имеют (сортировка,
отсечение, вывод), и в непокрытой части теории Соколова (квадратные матрицы).

## 1. Методологическая оговорка

Сверка велась с определением в редакции статьи Симакова В.А., которая ссылается
на Соколова [7]:

```
c[l_1..l_k, s_1..s_λ, m_1..m_v]
    = Σ по (c_1..c_μ)  a[l_1..l_k, s_1..s_λ, c_1..c_μ]
                     · b[s_1..s_λ, c_1..c_μ, m_1..m_v]
```

**Оригинал 1972 года в проекте отсутствует**, поэтому утверждать соответствие
первоисточнику дословно нельзя. Конкретно не проверены:

* порядок групп индексов в оригинальной записи (у Соколова возможна иная
  конвенция расположения λ- и μ-групп, что меняет каноническую раскладку осей,
  но не математическое содержание операции);
* терминология (что именно Соколов называет рангом, порядком и измерением);
* область определения операции для матриц с индексами разной природы.

Это первое, что следует закрыть перед публикацией: сверить §1.1 техпроекта
с оригинальной формулировкой. Содержательно операция от этого не изменится —
изменится лишь запись раскладки в `build_einsum`.

**Что дал поиск по открытым источникам.** Книгу Соколова 1972 года найти не
удалось. Найден перспективный обходной путь: В.С. Муха использует нотацию
свёрнутого произведения и ссылается на собственную монографию «Анализ
многомерных данных» (2004). Подробнее о поиске —
[аудит концепции машины](Соответствие%20концепции%20алгебраической%20машины.md), §0.1.

**Конвенция подтверждена по вторичному источнику.** Работа Мунермана и
Мунермана (2022), полученная позже и ссылающаяся прямо на Соколова, даёт
определение в виде A = a_lsc, B = b_scm, C = c_lsm с формулой
c_lsm = Σ a_lsc · b_scm и с рангом r = p + q − λ − 2μ. Это **в точности**
раскладка, реализованная в `build_einsum`, и та же арифметика рангов, что
доказана в аксиоме A2. Риск расхождения в конвенции, названный выше главным,
тем самым снят — с оговоркой, что подтверждение вторичное, а не по оригиналу
1972 года.

Оттуда же взята установившаяся терминология: общие индексы называются
**скоттовыми** (λ, сохраняются) и **кэлиевыми** (μ, свёртываются). Она внесена
в документацию ядра и в статью.

## 2. Уровень I: сама операция

### 2.1 Соответствие определению

Реализация сверена с прямым вычислением по определению (тройной цикл,
`convolve_naive`) для всех сочетаний λ, μ ∈ {0, 1, 2}: максимальное отклонение
**8.9·10⁻¹⁶**, то есть на уровне машинной точности.

Раскладка осей канонизирована ровно так, как в определении:

```
A: [l₁..l_k | s₁..s_λ | c₁..c_μ]
B:           [s₁..s_λ | c₁..c_μ | m₁..m_v]
C: [l₁..l_k | s₁..s_λ |           m₁..m_v]
```

Пример из статьи (ранг A = 6, ранг B = 9, (2,3)-свёртка) воспроизводится
посимвольно: `abcdef,bcdefghij->abcghij`.

### 2.2 Проверенные алгебраические законы

| Закон | Формулировка | Статус | Тест |
|---|---|---|---|
| Арифметика рангов | `rank(A∗B) = rank A + rank B − λ − 2μ` | ✓ | `test_rank_arithmetic` |
| Раскладка индексов | группы `[L\|S\|C] × [S\|C\|M] → [L\|S\|M]` | ✓ | `test_index_layout_follows_sokolov_grouping` |
| Дистрибутивность справа | `A∗(B+C) = A∗B + A∗C` | ✓ | `test_distributive_over_addition` |
| Дистрибутивность слева | `(A+B)∗C = A∗C + B∗C` | ✓ | `test_distributive_over_addition` |
| Однородность | `(αA)∗B = A∗(αB) = α(A∗B)` | ✓ | `test_homogeneous_in_both_arguments` |
| Ассоциативность при λ = 0 | `(A∗B)∗C = A∗(B∗C)` | ✓ | `test_associative_when_lambda_zero` |
| Ассоциативность при λ > 0 | при λ-оси, общей для всех операндов | ✓ | `test_associative_when_lambda_axis_shared_by_all` |
| Некоммутативность | `A∗B ≠ B∗A` | ✓ (как и должно быть) | `test_not_commutative` |
| Правая единица | `A ∗ E = A`, `E[s,c,m] = δ(c,m)` | ✓ | `test_right_unit_for_mu_one/two` |
| Левая единица (ранг 2) | `I ∗ A = A` | ✓ | `test_left_unit_for_rank_two` |
| Транспонирование | `(A∗B)ᵀ = Bᵀ ∗ Aᵀ` по группам индексов | ✓ | `test_transposition_law` |
| Нулевой элемент | `A ∗ 0 = 0`, `A + 0 = A` | ✓ | `test_convolution_with_zero_gives_zero` |

Единичный элемент был **добавлен в реализацию по итогам этого аудита**
(`amdb.core.unit_matrix`): до аудита он существовал только неявно.

### 2.3 Частные случаи

Операция корректно вырождается в известные:

| λ, μ | Что получается | Тест |
|---|---|---|
| (0, 0) | тензорное (внешнее) произведение | `test_reduces_to_outer_product` |
| (0, 1), ранг 2 | обычное умножение матриц | `test_reduces_to_matrix_multiplication` |
| (0, μ) | `tensordot` — свёртка по μ осям | `test_reduces_to_tensordot` |
| (λ, 0) | произведение с сохранением общей оси | `test_lambda_only_product_keeps_shared_axis` |

Это существенно: если бы реализация была «einsum под видом Соколова», согласия
в вырожденных случаях могло бы не быть.

### 2.4 Существенное ограничение, выявленное аудитом

Ассоциативность (λ, μ)-произведения выполняется **относительно фиксированного
набора ролей индексов**. Если при перегруппировке λ-ось становится μ-осью,
результат меняется — что естественно, но накладывает требование на оптимизатор:
переставляя порядок свёрток, он обязан сохранять роли, а не только имена осей.
Реализация это требование соблюдает (`test_associativity_fails_when_lambda_axis_is_dropped_midway`
фиксирует различие, `binary_decomposition` вычисляет роли на каждом шаге).

## 3. Уровень II: алгебра как система операций

### 3.1 Что реализовано

| Операция Соколова | Модуль | Состояние |
|---|---|---|
| (λ, μ)-свёрнутое произведение | `core/convolve.py` | ✓ |
| Сложение и вычитание матриц | `core/mdm.py` | ✓ (с выравниванием по именам осей) |
| Умножение на скаляр | `core/mdm.py` | ✓ |
| Транспонирование (перестановка индексов) | `core/mdm.py` | ✓ |
| Проекция (свёртка по осям) | `core/mdm.py` | ✓ |
| Срез (фиксация индексов) | `core/mdm.py` | ✓ |
| Внутренняя свёртка по паре собственных индексов (обобщение следа) | `core/ops.py` | ✓ *(добавлено по итогам аудита)* |
| Единичная матрица | `core/convolve.py` | ✓ *(добавлено по итогам аудита)* |
| Нулевая матрица | тривиально | ✓ |

Внутренняя свёртка `internal_convolution(A, i, j) = Σ_k A[…, k, …, k, …]` —
самостоятельная операция алгебры: она свёртывает индексы **одной** матрицы и к
бинарному произведению не сводится. До аудита её в реализации не было.

### 3.2 Чего нет

| Не реализовано | Почему это важно | Нужно ли для OLAP |
|---|---|---|
| Определитель многомерной матрицы | Часть теории Соколова для квадратных матриц чётного ранга | Нет |
| Обратная матрица, решение матричных уравнений | Там же | Нет |
| Классы симметричных/кососимметричных матриц, ориентация | Существенная часть книги 1972 г. | Нет |
| Теория квадратных многомерных матриц (все индексы одной длины) | AMDB работает с «прямоугольными» кубами — оси разной мощности | Нет |

**Честная формулировка:** реализована *мультипликативно-аддитивная часть*
алгебры Соколова — та, на которой строится машина баз данных. Утверждение
«реализована алгебра многомерных матриц Соколова» без оговорки было бы
преувеличением; корректно — «реализовано (λ, μ)-свёрнутое произведение и
сопутствующие операции алгебры Соколова».

## 4. Уровень III: машина баз данных

### 4.1 Ключевой вопрос

`einsum('abc,b,cd,a->ad', …)` — это **не** операция алгебры Соколова: её
операция бинарна, а здесь четыре операнда. Вопрос: является ли план запроса
композицией операций алгебры или чем-то иным?

### 4.2 Ответ: является, и это предъявляется

Добавлена функция `Database.sokolov(sql)`, которая раскладывает план в цепочку
бинарных (λ, μ)-произведений с явными ролями индексов:

```bash
python -m amdb --db mybase sokolov "SELECT customer, month, SUM(quantity * price) AS rev FROM sales JOIN product ON sales.product = product.product WHERE region = 'Смоленск' GROUP BY customer, month"
```

```
rev: SUM
    слагаемое с коэффициентом +1:
      1. [customer, product, date] ∗ [product] -> [customer, date]   (0,1)-свёртка; μ: product
      2. [date, month] ∗ [customer, date] -> [month, customer]       (0,1)-свёртка; μ: date
      3. [customer] ∗ [month, customer] -> [customer, month]         (1,0)-свёртка; λ: customer
```

Каждый шаг — законное (λ, μ)-произведение. Тест
`test_query_plan_decomposes_into_binary_sokolov_products` **исполняет эту
цепочку операциями ядра и сверяет результат с единым вызовом einsum**:
относительное расхождение < 10⁻¹².

То есть композиционность не постулируется, а проверяется численно.

Отдельно оговаривается тонкость: в (λ, μ)-произведении свободные индексы по
определению сохраняются. Если einsum одним вызовом ещё и суммирует свободную
ось, алгебраически это **второй** шаг — (0, μ)-свёртка с матрицей из единиц.
Разложение показывает такие шаги явно (`∗ 𝟙[…]`), не пряча их.

### 4.3 Соответствие конструкций SQL операциям алгебры

| SQL | Операция алгебры | В алгебре? |
|---|---|---|
| `JOIN` по ключу, ключ в `GROUP BY` | λ-индекс произведения | ✓ |
| `JOIN` по ключу, ключ под агрегатом | μ-индекс произведения | ✓ |
| `SUM` по остальным осям | (0, μ)-свёртка | ✓ |
| `WHERE` | умножение на 0/1-матрицу (маску) | ✓ |
| `ROLLUP` по иерархии | (0,1)-свёртка с матрицей перехода | ✓ |
| `COUNT(*)` | (0, μ)-свёртка счётного куба | ✓ |
| `AVG` | отношение двух свёрток | ✓ (поэлементное деление — операция над матрицами) |
| `SUM(a*b − c)` | линейная комбинация двух произведений | ✓ (по билинейности) |
| Оконная сумма | умножение на треугольную матрицу | ✓ |
| Разграничение доступа | умножение на матрицу прав | ✓ |
| `MIN` / `MAX` | (λ, μ)-произведение над полукольцом (max, ·) / (min, ·) | ✓ **с оговоркой, см. §5** |
| `COUNT(DISTINCT)` | — | ✗ не реализовано |
| `HAVING`, `ORDER BY`, `LIMIT` | — | ✗ по природе вне алгебры |

### 4.4 Об изоморфизме реляционной и матричной моделей

Тезис Мунермана об изоморфизме теоретико-множественной и многомерно-матричной
моделей в проекте **используется, но не доказывается**. Реализация даёт лишь
эмпирическое подтверждение в одну сторону: 22 дифференциальных теста
(`tests/test_queries.py`) показывают, что для поддерживаемого подмножества SQL
матричное исполнение совпадает с реляционным оракулом с относительной
погрешностью ≤ 10⁻¹². Это верификация, а не доказательство, и в тексте работы
её нельзя выдавать за доказательство изоморфизма.

## 5. Где реализация выходит за пределы алгебры и что с этим сделано

### 5.1 MIN/MAX: было «вне алгебры», стало «над другим полукольцом»

Алгебра Соколова строится над кольцом (ℝ, +, ·): в определении произведения
сложение агрегирует, умножение комбинирует. `MIN`/`MAX` через эту пару операций
не выражаются — в первой редакции реализации они исполнялись обычной редукцией
и честно помечались как выходящие за рамки модели.

По итогам аудита добавлен модуль [`amdb/core/semiring.py`](../amdb/core/semiring.py):
(λ, μ)-свёрнутое произведение над произвольным полукольцом. Определение
сохраняет форму, меняется лишь пара операций:

| Полукольцо | Смысл |
|---|---|
| (+, ·) | исходное произведение Соколова, агрегат `SUM` |
| (max, ·) | агрегат `MAX` |
| (min, ·) | агрегат `MIN` |
| (max, +) | тропическое: критический путь |
| (min, +) | тропическое: кратчайшие пути |

Проверено, что над (+, ·) обобщённая операция совпадает с исходной, что
(max, ·) и (min, ·) воспроизводят `MAX`/`MIN`-агрегацию, и что (min, +) на
матрицах смежности даёт кратчайшие пути (`test_tropical_semiring_computes_shortest_paths`)
— последнее показывает, что обобщение действительно полукольцевое, а не
подгонка под нужный ответ.

**Таким образом MIN/MAX перестают быть исключением из модели: это то же
(λ, μ)-произведение над другим полукольцом.** Для диссертации это,
по-видимому, самостоятельный результат.

Практическая оговорка: `einsum` и BLAS работают только с (+, ·). Прочие
полукольца требуют материализации промежуточного массива |L|·|S|·|C|·|M| и
считаются на порядки медленнее, поэтому исполнитель запросов по-прежнему
использует для `MIN`/`MAX` прямую редукцию — она даёт тот же результат дешевле.
Полукольцевая реализация служит обоснованием, а не рабочим путём.

### 5.2 Что остаётся вне алгебры

**`COUNT(DISTINCT ...)`** — не реализовано. Направление, в котором это можно
внести в модель: полукольцо множеств (∪, ×) или коммутативный моноид
HyperLogLog-скетчей относительно слияния. Формулировать это как результат
преждевременно — только как гипотезу.

**`HAVING`, `ORDER BY`, `LIMIT`, форматирование вывода** — операции над
результирующей таблицей, а не над гиперкубами. Они вне алгебры по природе, и
это не дефект: в реляционной алгебре сортировки тоже нет.

**Гранулярность MIN/MAX.** Ячейка куба хранит агрегат, поэтому `MAX` работает
по ячейкам, а не по исходным записям. Это свойство *модели данных* (отображения
отношения в гиперкуб), а не алгебры.

## 6. Итоговая оценка и что доделать

### 6.1 Что можно утверждать в тексте работы

* «Реализовано (λ, μ)-свёрнутое произведение многомерных матриц в смысле
  Соколова; соответствие определению и алгебраическим законам подтверждено
  46 автоматическими тестами» — **можно, это проверено**.
* «Исполнение SQL-запроса является композицией (λ, μ)-свёрнутых произведений»
  — **можно для линейных агрегатов, разложение предъявляется и верифицируется
  численно**.
* «MIN/MAX выражаются как (λ, μ)-произведение над полукольцом (max, ·)
  **на неотрицательных мерах**» — можно, доказано и проверено. Без оговорки о
  неотрицательности — нельзя: (ℝ, max, ·) полукольцом не является.

### 6.2 Что утверждать нельзя без доработки

| Утверждение | Чего не хватает |
|---|---|
| «Реализована алгебра многомерных матриц Соколова» | Нет определителя, обращения, теории квадратных матриц. Корректнее: «реализована мультипликативно-аддитивная часть» |
| «Соответствует оригиналу Соколова 1972 г.» | Сверка велась с редакцией определения из статьи; оригинал не проверялся |
| «Доказан изоморфизм реляционной и матричной моделей» | В проекте изоморфизм используется как известный результат Мунермана; получено лишь эмпирическое подтверждение на 22 запросах |
| «Все операции OLAP выражаются через свёрнутое произведение» | `COUNT DISTINCT` не выражен; сортировка и отсечение вне алгебры |

### 6.3 План доработки по приоритету

1. **Сверить определение с оригиналом Соколова (1972).** Частично закрыто:
   раскладка осей и арифметика рангов подтверждены по работе Мунермана (2022),
   ссылающейся на Соколова напрямую. Остаётся сверка по самому оригиналу —
   обходной путь через монографию Мухи В.С. (2004).
2. ~~Оформить полукольцевое обобщение как результат~~ — **выполнено**:
   [Математическое обоснование](Математическое%20обоснование.md), §5, теорема 4.
   Существенное уточнение, найденное при доказательстве: (max, ·) образует
   полукольцо **только на неотрицательных значениях**, и на знакопеременных
   данных ассоциативность свёрнутого произведения нарушается — а с ней и
   корректность переписывания плана.
3. ~~Дополнить бинарное разложение доказательством корректности~~ —
   **выполнено**: теорема 1 и следствия 1–2,
   [там же](Математическое%20обоснование.md), §3.
4. *(опционально)* Реализовать определитель и обращение для квадратных матриц
   чётного ранга — тогда формулировка «реализована алгебра» станет законной.
   Для OLAP не нужно, для полноты изложения теории — да.

## 7. Второй аудит: концепция машины

Настоящий документ отвечает на вопрос об **операции** — является ли она
(λ, μ)-свёрнутым произведением. Вопрос о том, является ли комплекс **машиной**
в смысле двухосновной алгебраической системы (концепция В.И. Мунермана),
разобран отдельно: [«Является ли AMDB алгебраической машиной баз
данных?»](Соответствие%20концепции%20алгебраической%20машины.md).

Кратко его вывод: по устройству — да (данные и операции разнесены по сортам,
план запроса есть терм, оптимизация есть переписывание терма с сохранением
интерпретации, проверено на всех 18 порядках свёрток), но машина **не
универсальна** и комплекс **не программно-аппаратный**.
