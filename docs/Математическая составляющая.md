## 2. Носители и структуры

### 2.1 Полукольцо коэффициентов

Базовая структура — **коммутативное полукольцо**
**K** = (K, ⊕, ⊗, 0̄, 1̄): обе операции ассоциативны и коммутативны, ⊗
дистрибутивно относительно ⊕, 0̄ нейтрален по ⊕ и поглощает по ⊗, 1̄
нейтрален по ⊗. Существования обратного по ⊕ не требуется — это важно, потому
что именно отказ от него открывает дорогу тропическим полукольцам (§9).

Классический случай алгебры Соколова — K = (ℝ, +, ·). В реализации
коэффициенты хранятся в `float64` (см. §10).

### 2.2 Измерения

**Определение.** Измерение d — конечное упорядоченное множество значений
V_d = {v₀, …, v_{n−1}} вместе с биекцией ord_d: V_d → {0, …, n−1}.
Число n = |d| называем мощностью измерения.

Биекция ord_d («словарь измерения») — не деталь реализации, а часть
математической конструкции: именно она превращает произвольные значения
(строки, даты, идентификаторы) в индексы матрицы. Существенное требование —
**ord_d монотонно расширяемо**: при дозагрузке новые значения получают
следующие ординалы, а существующие сохраняют свои. Без этого ранее построенные
матрицы перестали бы быть согласованными с индексацией.

У измерения могут быть **атрибуты** — отображения α: V_d → A. Они участвуют в
построении масок (§5.2), но не образуют осей.

### 2.3 Многомерная матрица

**Определение.** Пусть d₁, …, d_p — измерения. Многомерная матрица ранга p —
отображение

> A: {0..|d₁|−1} × … × {0..|d_p|−1} → K

Множество всех таких матриц обозначаем 𝕄. Ранг p — число осей; вектор
(|d₁|, …, |d_p|) — форма. В отличие от классической теории квадратных
многомерных матриц, мощности осей здесь произвольны («прямоугольный» случай),
что достаточно для произведения, но исключает теорию определителя и обращения.

Каждой оси сопоставлено **имя измерения**; матрица — это пара
(массив, кортеж имён). Именование осей делает роли индексов в произведении
выводимыми автоматически: общая ось — это ось с общим именем.

### 2.4 Иерархии

**Определение.** Иерархия — отображение h: V_c → V_p из значений дочернего
измерения в значения родительского. Ей сопоставляется **матрица перехода**

> H^{c→p}[i, j] = 1̄, если h(v_i) = v_j, и 0̄ иначе

размера |c| × |p|. Матрица H строго стохастическая по строкам (в каждой строке
ровно одна единица), то есть h всюду определено и однозначно.

**Композиция.** Для цепочки h₂ ∘ h₁ (например, дата → месяц → квартал)
матрица перехода есть матричное произведение:

> H^{c→q} = H^{c→p} · H^{p→q}

Это прямая проверка: (H^{c→p}H^{p→q})[i,k] = Σ_j [h₁(v_i)=u_j]·[h₂(u_j)=w_k]
= [h₂(h₁(v_i)) = w_k], поскольку ровно одно слагаемое ненулевое.

Следствие: иерархии образуют категорию, и `ROLLUP` по любой цепочке — одна
(0,1)-свёртка с произведением матриц перехода.

## 3. Отображение реляционной модели в матричную

Это узловой пункт: именно здесь возникает и обосновывается тезис об
изоморфизме моделей, и именно здесь он оказывается верным лишь при условии.

### 3.1 Определение отображения

Пусть R — мультимножество кортежей (фактов), π: R → V_{d₁} × … × V_{d_p} —
проекция на набор измерений, m: R → K — мера. Определим

> **φ(R)[x] = ⊕_{r ∈ π⁻¹(x)} m(r)**,  x ∈ V_{d₁} × … × V_{d_p}

то есть ячейка гиперкуба есть ⊕-сумма меры по **слою** (прообразу точки).
В терминах теории меры это прямой образ (pushforward) меры m вдоль π.

Реализация вычисляет φ векторизованно: координаты кортежей сворачиваются в
линейный индекс (`ravel_multi_index`), после чего суммирование по слоям —
это `bincount` со взвешиванием. Сложность O(|R| · p) без построения слоёв
явно.

### 3.2 Свойства отображения

**Утверждение (гомоморфность).** φ(R ⊎ R′) = φ(R) ⊕ φ(R′), где ⊎ —
мультимножественное объединение.

*Обоснование.* Слой объединения есть объединение слоёв, а ⊕-сумма по
объединению непересекающихся частей равна ⊕-сумме сумм. ∎

**Теорема 5 (условие изоморфизма).** Отображение φ инъективно на отношениях
с ненулевыми мерами тогда и только тогда, когда π инъективно на R, то есть
набор измерений (d₁, …, d_p) является **ключом** отношения фактов.

*Обоснование.* Если π инъективно, каждый слой содержит не более одного
кортежа, значит φ(R)[x] = m(r) для единственного r с π(r) = x, и R
восстанавливается по φ(R) (ненулевые ячейки ↔ кортежи). Обратно, если
π(r₁) = π(r₂) для различных r₁ ≠ r₂, то любые два разбиения суммы
m(r₁) ⊕ m(r₂) между двумя кортежами дают одну и ту же матрицу — φ не
инъективно. ∎

*Проверка:* `test_mapping_is_injective_when_dimensions_form_a_key`,
`test_mapping_is_not_injective_when_dimensions_are_not_a_key`,
`test_mapping_is_a_homomorphism_for_sum`.

**Замечание об области, на которой утверждение верно.** Ограничение «на
отношениях с ненулевыми мерами» существенно. Ячейка со значением 0̄ неотличима
от ячейки с пустым слоем, поэтому кортеж с нулевой мерой отображением
теряется. На знакопеременных мерах теряется больше: слой из двух кортежей
с мерами +a и −a даёт ту же ячейку, что и пустой слой, — инъективность
нарушается **даже при инъективном π**, то есть при выполнении условия теоремы 5.
Следовательно, в полной строгости условие звучит так: φ инъективно тогда и
только тогда, когда π инъективно на R **и** мера строго положительна. Пара
(φ_sum, φ_count) из следствия (в) снимает первую часть проблемы — она отличает
пустой слой от слоя с нулевой суммой, — но не вторую: два кортежа, дающие
в сумме ноль, счётным кубом различаются от пустого слоя, однако само
распределение меры внутри слоя по-прежнему не восстанавливается.

### 3.3 Следствия — важные для практики и для формулировок в работе

**(а) Изоморфизм не универсален.** Утверждение «между реляционной и
многомерно-матричной моделями существует изоморфизм» верно **на уровне
экземпляров** лишь при условии теоремы 5. В общем случае φ — сюръективный
гомоморфизм, но не изоморфизм. Это согласуется с формулировкой, найденной в
доступной работе Мунермана и Мунермана (2015), где соответствие названо
таким, которое «может быть установлено» — гомоморфное **либо** изоморфное.

**(б) Гранулярность MIN/MAX.** Так как слой схлопывается ⊕-суммой,
max по ячейкам ≠ max по кортежам, когда слой содержит более одного кортежа.
Пример: кортежи с мерами 3, 5 в одной ячейке и 4 в другой дают куб {8, 4};
максимум по кубу 8, по кортежам 5. Это не дефект реализации, а свойство
отображения φ.

**(в) Счётный куб как уточняющий инвариант.** Пара (φ_sum(R), φ_count(R)),
где φ_count использует меру ≡ 1̄, различает больше, чем φ_sum: она сохраняет
мощность каждого слоя. Именно поэтому `COUNT(*)` и `AVG` в AMDB точны, а не
считают «непустые ячейки». Полный инвариант (сама R) требовал бы хранения
распределения меры внутри слоя, то есть возврата к отношению.

**(г) Выбор гранулярности — проектное решение.** Чем мельче набор измерений
факта, тем ближе φ к инъективности и тем богаче множество корректно
выразимых агрегатов, но тем больше ячеек. Это математическая формулировка
компромисса между точностью модели и размером гиперкуба.

## 4. (λ, μ)-свёрнутое произведение

### 4.1 Определение

Пусть

* A: I_L × I_S × I_C → K ранга k + λ + μ,
* B: I_S × I_C × I_M → K ранга λ + μ + v,

где группы I_S (мощность λ) и I_C (мощность μ) у сомножителей совпадают.
Тогда

> **(A ∗_{λ,μ} B)_{L,S,M} = ⊕_{C ∈ I_C} A_{L,S,C} ⊗ B_{S,C,M}**

Роли индексов:

| Группа | Свойство | Смысл в запросе |
|---|---|---|
| L | только у A | измерение, уникальное для первого факта |
| **S (λ)** | общая, **сохраняется** | ключ соединения, остающийся в `GROUP BY` |
| **C (μ)** | общая, **свёртывается** | ключ соединения, схлопываемый агрегатом |
| M | только у B | измерение, уникальное для второго факта |

Это и есть мостик между моделями: **соединение и агрегация — одна операция**,
различающаяся лишь тем, попал общий индекс в результат или нет.

### 4.2 Свойства

Все доказаны в [Математическом обосновании](Математическое%20обоснование.md), §2.

| Свойство | Формулировка | Условия |
|---|---|---|
| Замкнутость | A ∗ B ∈ 𝕄 | — |
| Ранг | rank(A ∗ B) = rank A + rank B − λ − 2μ | — |
| Билинейность | дистрибутивность по ⊕ и однородность по ⊗ в обоих аргументах | — |
| Ассоциативность | (A ∗ B) ∗ D = A ∗ (B ∗ D) | λ-группа должна оставаться λ-группой во всех произведениях |
| Некоммутативность | A ∗ B ≠ B ∗ A в общем случае | — |
| Единица | A ∗ E = A, E_{S,C,M} = δ(C, M) | I_M = I_C |
| Нуль | A ∗ 0̄ = 0̄ | — |
| Транспонирование | (A ∗ B)^T = B^T ∗ A^T | ⊗ коммутативна |

Требование к ассоциативности не формальность: если при перегруппировке
λ-индекс становится μ-индексом, равенство рушится. Отсюда обязанность
оптимизатора сохранять **роли**, а не только имена осей.

### 4.3 Частные случаи

| λ | μ | Что получается |
|---|---|---|
| 0 | 0 | тензорное (внешнее) произведение |
| 0 | 1, ранги 2 | обычное умножение матриц |
| 0 | μ | свёртка по μ осям (`tensordot`) |
| λ | 0 | произведение с сохранением общей оси (диагональное) |

Согласие в вырожденных случаях — содержательная проверка: реализация,
лишь имитирующая теорию, здесь бы разошлась.

Случай λ ≥ 1, μ = 0 заслуживает отдельного внимания: суммирования нет вовсе,
операция чисто мультипликативна, и ранг результата **растёт** (r = p + q − λ).
Это не патология, а рабочий случай. В работе Морозова, Мунермана и Симакова
(2022) на нём построено решение задачи о маршрутах в графе: (1, 0)-степень
матрицы смежности G имеет ранг k + 1, и

> G²_{i,j,k} = G_{i,j} · G_{j,k} ≠ 0̄  ⟺  существует маршрут i → j → k,

то есть набор значений индексов ненейтрального элемента есть сама
последовательность вершин маршрута. Сравнение с (0, 1)-произведением, то есть
с обычным умножением матриц, показывает, что именно даёт скоттов индекс:
Σ_j G_{i,j} G_{j,k} сохраняет число маршрутов, но теряет промежуточную
вершину, а значит и сами маршруты.

Этот случай служит и проверкой порядка параметров в обозначении (λ, μ),
который никакими алгебраическими тождествами не фиксируется: при обратном
прочтении (1, 0)-степень оказалась бы обычным умножением матриц и маршрутов
не дала бы. Сверка реализации с полным перебором маршрутов на графе из
названной работы вынесена в тест
`test_lambda_mu_convention_matches_the_published_routing_construction`.

### 4.4 Реализация через соглашение Эйнштейна

Каноническая раскладка осей A: [L | S | C], B: [S | C | M] → [L | S | M]
позволяет построить индексную строку механически. Для рангов 6 и 9 и (2,3)-свёртки:

```
abcdef,bcdefghij->abcghij
```

Ограничение реализации: `numpy.einsum` допускает не более **52** различных
индексов (a–z и A–Z); списочная форма лимит не снимает. Планы с бо́льшим
числом измерений разбиваются на цепочку парных произведений (§7.4), что
корректно по теореме 1.

## 5. Трансляция запросов

Транслятор реализует набор лемм, превращающих SQL-конструкции в операции
алгебры. Ниже — полный перечень.

### 5.1 Нормализация выражений (лемма 1)

Всякое выражение из мер, констант, операций +, −, × и деления на ненулевую
константу приводится к виду

> Σ_j α_j · Π_{m ∈ M_j} m

— линейной комбинации произведений мер. Доказательство — индукция по
структуре выражения с использованием дистрибутивности × над ±.

Следствие: `SUM(quantity·price − quantity)` даёт два независимых свёрнутых
произведения, результаты которых складываются с коэффициентами +1 и −1.
Это прямое применение билинейности (§4.2).

Деление на **меру** внутри агрегата невыразимо: `SUM(a/b)` не приводится к
линейной комбинации произведений. Транслятор отклоняет такой запрос, предлагая
эквивалент `SUM(a)/SUM(b)`, если он подходит по смыслу.

### 5.2 Селекция как операнд (лемма 2)

Пусть условие φ зависит от измерений d₁, …, d_t. Его **индикатор**

> χ^φ: I_{d₁} × … × I_{d_t} → {0̄, 1̄}

есть многомерная матрица. Тогда

> Σ_{ячейки, удовлетворяющие φ} A = Σ_{все ячейки} A ⊗ χ^φ

Обоснование: не удовлетворяющие ячейки умножаются на 0̄. Значит **селекция —
это добавление ещё одного операнда в то же стягивание**, а не отдельный
проход по данным.

Построение χ^φ по структуре условия:

| Конструкция | Индикатор |
|---|---|
| d = v | χ[i] = [v_i = v] — вектор по оси d |
| d IN (v₁…v_r) | χ[i] = [v_i ∈ {v₁…v_r}] |
| d BETWEEN a AND b | χ[i] = [a ≤ v_i ≤ b] (требует упорядоченного d) |
| α(d) = w для атрибута α | χ[i] = [α(v_i) = w] — тоже вектор по оси d |
| φ₁ AND φ₂ | два независимых операнда (конъюнкция = произведение) |
| φ₁ OR φ₂ | χ = 1̄ − (1̄ − χ₁)(1̄ − χ₂) на объединении осей |
| NOT φ | χ = 1̄ − χ^φ |

Конъюнкция остаётся **факторизованной** — два вектора вместо матрицы, что
экономит и память, и операции. Дизъюнкция по разным осям факторизации не
допускает: приходится материализовать совместный тензор ранга, равного числу
задействованных измерений. Это математическая причина, по которой `OR` между
разными измерениями дороже, чем `AND`.

Подзапрос `d IN (SELECT d FROM … WHERE ψ)` сводится к тому же: индикатор ψ
строится по атрибутам измерения d и даёт вектор по оси d.

### 5.3 Иерархия как операнд (лемма 3)

Группировка по родительскому измерению p, достижимому из оси c, есть
(0,1)-свёртка с матрицей перехода:

> (A ∗_{0,1} H^{c→p})_{…,p} = Σ_c A_{…,c} · H^{c→p}[c, p] = Σ_{c: h(c)=p} A_{…,c}

— в точности сумма по прообразу. Для цепочки иерархий берётся произведение
матриц (§2.4).

### 5.4 Агрегаты

| Агрегат | Представление | В алгебре над (+, ·) |
|---|---|---|
| `SUM(e)` | линейная комбинация свёрток по лемме 1 | да |
| `COUNT(*)` | свёртка счётного куба φ_count | да |
| `COUNT(x)` | свёртка индикатора непустых ячеек куба меры x | да |
| `AVG(e)` | отношение SUM и COUNT — поэлементное деление двух матриц | да (деление вне свёртки) |
| `MIN/MAX(x)` | редукция; см. §9 | **нет** над (+, ·) |
| `COUNT(DISTINCT x)` | — | нет, не реализовано |

**Утверждение (о непредставимости MIN/MAX).** MIN и MAX не выражаются никакой
линейной комбинацией (λ, μ)-произведений над (+, ·) с фиксированными
вспомогательными матрицами.

*Обоснование.* Свёрнутое произведение билинейно, поэтому любая такая
комбинация — линейная функция куба-меры, а значит аддитивная. Но
max((1,0)) + max((0,1)) = 2, тогда как max((1,0) + (0,1)) = max((1,1)) = 1. ∎

### 5.5 Оконные функции

Накопительная сумма вдоль оси t — умножение на **верхнетреугольную** матрицу
W[i, j] = [i ≤ j]:

> (A ∗ W)_{…,j} = Σ_i A_{…,i} · [i ≤ j] = Σ_{i ≤ j} A_{…,i}

Скользящее окно ширины w — ленточная матрица W[i, j] = [0 ≤ j − i ≤ w−1];
взвешенное окно — произвольная матрица весов. Один механизм покрывает
`UNBOUNDED PRECEDING`, `ROWS BETWEEN n PRECEDING AND CURRENT ROW` и
взвешенные скользящие средние.

Замечание: ориентация матрицы существенна. Для соглашения `[from, to]` нужна
именно **верхне**треугольная матрица; нижнетреугольная даёт накопление в
обратном порядке.

### 5.6 Разграничение доступа

Право роли на измерение d задаётся 0/1-вектором ρ_d по оси d. Ограниченный
запрос — тот же терм с дополнительными операндами ρ_d. Отсюда два следствия:

* запрещённые данные не участвуют в арифметике ни на одном промежуточном шаге
  (а не отфильтровываются после);
* по теореме 1 добавление операнда коммутирует с выбором порядка свёрток,
  то есть оптимизатор не может «оптимизировать» права доступа.

**Ограничение.** Маскирование умножением на 0̄ корректно для ⊕-агрегатов
(SUM, COUNT). Для MIN/MAX оно неверно: 0̄ стал бы ложным экстремумом. Там
права применяются выборкой разрешённых индексов (сужением носителя), что даёт
подматрицу — операцию среза, а не умножения.

### 5.7 Класс представимых запросов

**Теорема 2.** Всякий запрос вида

```
SELECT G, agg₁(e₁), …  FROM кубы  WHERE φ  GROUP BY G
```

где agg ∈ {SUM, COUNT, AVG}, каждое e — выражение из леммы 1, φ — произвольная
булева комбинация предикатов над измерениями и атрибутами, а каждое измерение
из G является осью куба либо достижимо по иерархии, — представим как линейная
комбинация (λ, μ)-свёрнутых произведений над (ℝ, +, ·).

Доказательство конструктивно и в точности повторяет работу транслятора:
лемма 1 даёт слагаемые, лемма 2 — операнд фильтра, лемма 3 — операнды
иерархий, выходной набор индексов полагается равным G.

## 6. План как терм алгебры

### 6.1 Многооперандное стягивание

Пусть матрицы A₁, …, A_n индексированы наборами имён X₁, …, X_n, а O — набор
выходных индексов. Определим

> F_O(A₁, …, A_n) = ⊕_{значения индексов из (⋃X_i) ∖ O} ⊗_i A_i

**Многооперандное стягивание не является операцией алгебры Соколова** — она
бинарна. Но:

**Теорема 1.** Для любого двоичного дерева (плана) p вычисление снизу вверх
бинарными (λ, μ)-произведениями даёт ev_p = F_O.

**Следствие 1.** ev_p = ev_{p′} для любых планов p, p′ — результат не зависит
от порядка свёрток.

Именно следствие 1 делает оптимизацию корректной. Проверено численно: для
терма из четырёх операндов перебраны все 18 порядков, расхождение 2.4·10⁻¹⁵.

### 6.2 Пример разложения

Запрос

```sql
SELECT customer, month, SUM(quantity * price)
FROM sales JOIN product ON sales.product = product.product
WHERE region = 'Смоленск'
GROUP BY customer, month
```

даёт терм из четырёх операндов и раскладывается в три бинарных произведения:

```
1. [customer, product, date] ∗ [product]        -> [customer, date]   (0,1); μ: product
2. [date, month] ∗ [customer, date]             -> [month, customer]  (0,1); μ: date
3. [customer] ∗ [month, customer]               -> [customer, month]  (1,0); λ: customer
```

Первые два шага — свёртки по товару и дате (агрегация), третий — умножение на
маску с сохранением оси клиента. Разложение получается командой
`amdb sokolov`, запись терма — `Database.term`.

Отдельная тонкость: в (λ, μ)-произведении свободные индексы по определению
**сохраняются**. Если einsum одним вызовом ещё и суммирует свободную ось,
алгебраически это второй шаг — (0, μ)-свёртка с матрицей из 1̄. Разложение
показывает такие шаги явно.

## 7. Модель стоимости и выбор порядка свёрток

### 7.1 Стоимость одного произведения

Для A: I_L × I_S × I_C и B: I_S × I_C × I_M, где |I_X| — произведение
мощностей осей группы X:

* число ⊗-операций: |I_L| · |I_S| · |I_C| · |I_M|
* число ⊕-операций: (|I_C| − 1) · |I_L| · |I_S| · |I_M|
* размер результата: |I_L| · |I_S| · |I_M| ячеек

Реализация оценивает стоимость как произведение мощностей **всех**
задействованных осей — это число умножений-сложений, с точностью до
константы совпадающее с обеими формулами.

### 7.2 Почему порядок важен: числовой пример

Для запроса §6.2 при |customer| = |product| = |date| = 100, |month| = 4:

| Стратегия | Операций |
|---|---|
| Стягивание всех операндов «в лоб» (по полному индексному пространству c×p×d×m) | 4·10⁷ |
| Оптимальный порядок: 10⁶ + 4·10⁴ + 4·10² | ≈ 1.04·10⁶ |

Выигрыш ≈ **38×** на одном лишь порядке, при том же результате. Наибольший
промежуточный тензор при оптимальном порядке — 10⁴ ячеек (customer × date).
Именно эти два числа печатает `amdb explain`.

### 7.3 Задача выбора порядка

Формально: среди всех двоичных деревьев над n операндами найти дерево
минимальной суммарной стоимости. Задача эквивалентна поиску оптимального
порядка стягивания тензорной сети и в общем случае **NP-трудна**. Число
различных деревьев растёт как двойной факториал (2n−3)!!:

| n | Деревьев (2n−3)!! | Последовательностей парных стягиваний |
|---:|---:|---:|
| 3 | 3 | 3 |
| 4 | **15** | **18** |
| 5 | 105 | 180 |
| 10 | 34 459 425 | 2 571 912 000 |

Второй столбец больше первого потому, что независимые стягивания можно
выполнить в любом порядке, получив одно и то же дерево. Тест инвариантности
(§6.1) перебирает именно **последовательности** — 18 для четырёх операндов, —
то есть проверяет условие строже, чем перебор деревьев.

Стратегия реализации:

* n ≤ 8 — полный перебор динамическим программированием по подмножествам
  (`optimize="optimal"`);
* n > 8 — жадный алгоритм: на каждом шаге выбирается пара с наименьшей
  стоимостью (`optimize="greedy"`);
* найденный порядок **кэшируется** вместе с планом: пересчёт при каждом вызове
  на малых операндах стоит дороже самой свёртки.

Дополнительно проверяется бюджет памяти: если наибольший промежуточный тензор
превышает установленный лимит (по умолчанию 4 ГиБ), план отклоняется **до**
аллокации с объяснением, а не падает по нехватке памяти во время счёта.

### 7.4 Декомпозиция при превышении лимита индексов

Если число различных индексов превышает 52, единая einsum-строка непостроима.
План разбивается на цепочку парных произведений, где каждый промежуточный
результат сохраняет только оси, нужные дальше или входящие в выход.
Корректность — следствие 2 теоремы 1: двоичное дерево существует для любого n,
а его вычисление даёт то же F_O. Побочный эффект — обычно **меньший** объём
вычислений, поскольку промежуточные результаты сразу проецируются.

## 8. Разреженные вычисления

### 8.1 Носитель

Разреженная многомерная матрица хранится в координатном формате (COO): пара
(координаты ∈ ℤ^{nnz × p}, значения ∈ K^{nnz}) плюс форма. Ячейки, не
представленные в списке, равны 0̄. Каноническая форма получается сортировкой
по линейному индексу, суммированием дубликатов и отбрасыванием нулей.

Фактор заполнения: θ = nnz / Π|d_i|.

### 8.2 Сложность свёрток

**COO × плотная.** Для каждой ненулевой ячейки A выбирается соответствующий
срез B и умножается:

> число ⊗-операций: nnz_A · |I_M|

против |I_L|·|I_S|·|I_C|·|I_M| в плотном случае. Выигрыш — множитель θ.

**COO × COO.** Хеш-соединение по общим индексам: ключом служит линейный индекс
группы S ∪ C, и для каждого ключа берётся декартово произведение
соответствующих подсписков:

> число ⊗-операций: Σ_k |A_k| · |B_k|

где k пробегает общие ключи. Худший случай nnz_A · nnz_B (все ячейки в одном
слое), лучший — max(nnz_A, nnz_B).

### 8.2.1 Сохранение ассоциативности на разреженном пути

Теорема о разложении и её следствие о независимости результата от порядка
свёрток доказаны для алгебраических тождеств и от представления не зависят.
Однако разреженные ядра накапливают вклады в ином порядке, чем плотные
(хеш-соединение обходит ключи в порядке хеш-таблицы, плотный путь — в порядке
индексов), а сложение чисел с плавающей точкой не ассоциативно. Формально это
означает, что следствие выполняется точно над ℝ и лишь приближённо в машинной
арифметике — как и на плотном пути.

Проверено численно: цепочка из трёх разреженных гиперкубов рангов 3, свёрнутая
в обоих порядках — (A ∗ B) ∗ C и A ∗ (B ∗ C), — дала максимальное расхождение
2.2·10⁻¹⁶ при значениях единичного масштаба, то есть на уровне машинного
эпсилона для float64; оба порядка совпали и с плотным эталоном, вычисленным
одним einsum. Следовательно, переписывание плана корректно независимо от
выбранного представления, и оптимизатору не требуется знать, какое из них
будет выбрано исполнителем.

### 8.3 Критерий выбора представления

Плотное хранение требует s · Π|d_i| байт (s — размер элемента), разреженное —
nnz · (s + 8p). Разреженное выгоднее по памяти при

> θ < s / (s + 8p)

что для s = 8 (float64) и p = 3 даёт θ < 0.25. Реализация использует более
строгий порог θ < 0.02, и вот почему: **разреженный путь выигрывает память,
но проигрывает время**. Плотная свёртка уходит в BLAS с его блочными
алгоритмами и векторизацией, разреженная — в собственное хеш-соединение.
Измерения показывают проигрыш в 5–10 раз по времени при выигрыше в 10–50 раз
по памяти. Поэтому разреженное представление включается тогда, когда плотное
не помещается в память, а не «для скорости».

## 9. Обобщение на полукольца

### 9.1 Теорема 4

Ни одно из доказательств §4.2 и §6 не использует существования обратного по
⊕. Следовательно определение свёрнутого произведения корректно, а все
перечисленные свойства и теорема 1 справедливы над **любым коммутативным
полукольцом**.

Это не абстрактное обобщение ради обобщения: оно даёт формально корректное
место агрегатам, невыразимым над (+, ·).

| Полукольцо | Агрегат / задача |
|---|---|
| (ℝ, +, ·) | SUM — исходная алгебра Соколова |
| (ℝ≥0, max, ·) | MAX |
| (ℝ≥0 ∪ {+∞}, min, ·) | MIN |
| (ℝ ∪ {−∞}, max, +) | критический путь |
| (ℝ ∪ {+∞}, min, +) | кратчайшие пути |

### 9.2 Области определения — существенное ограничение

**Утверждение 5.** (ℝ, max, ·) полукольцом **не является**: дистрибутивность
нарушается на отрицательных множителях.

> max(2, 3) · (−1) = −3,  тогда как  max(2·(−1), 3·(−1)) = −2

**Следствие.** На знакопеременных данных теорема 1 для (max, ·) неверна:
разные порядки свёрток дают разные ответы. Численно — расхождение порядка 1.1
при данных единичного масштаба на цепочке из трёх матриц. То есть **главное
свойство алгебраической машины — корректность переписывания терма — на таких
данных теряется**.

Практический вывод: заявление «MIN/MAX — свёрнутое произведение над
полукольцом» корректно **только с оговоркой о неотрицательности мер**. Для
OLAP-мер (количества, цены) условие обычно выполняется, но обязано быть
проверено, а не подразумеваться. Реализация проверяет знак операндов и
отклоняет вычисление, если проверка не снята явно.

**Утверждение 6.** Тропические полукольца (ℝ ∪ {+∞}, min, +) и
(ℝ ∪ {−∞}, max, +) — полукольца на всей числовой оси, поскольку сдвиг
сохраняет порядок: min(x, y) + z = min(x + z, y + z) для любого z.

Классическая иллюстрация: повторное (min, +)-произведение матрицы смежности
графа даёт матрицу кратчайших путей — то же свёрнутое произведение, иная пара
операций.

### 9.3 Цена обобщения

`einsum` и BLAS реализуют только (+, ·). Прочие полукольца вычисляются
широковещательным произведением с последующей редукцией, что требует
материализации промежуточного массива размера |I_L|·|I_S|·|I_C|·|I_M| —
того самого, которого оптимальный порядок свёрток позволяет избежать.
Поэтому в исполнителе MIN/MAX считаются прямой редукцией: результат тот же,
стоимость ниже. Полукольцевая реализация служит **обоснованием**, а не
рабочим путём.

## 10. Численные аспекты

### 10.1 Погрешность суммирования

Свёртка есть сумма произведений, поэтому точность определяется точностью
суммирования. NumPy использует попарное (pairwise) суммирование, дающее оценку
относительной погрешности O(log n · ε) вместо O(n · ε) для наивного цикла,
где ε — машинный эпсилон.

Измерено на сумме 10⁷ случайных слагаемых:

| Тип | ε | Относительная погрешность |
|---|---|---|
| `float32` | ≈ 1.2·10⁻⁷ | 9.1·10⁻⁷ |
| `float64` | ≈ 2.2·10⁻¹⁶ | < 10⁻¹⁵ |

### 10.2 Почему `float64` по умолчанию

Погрешность 10⁻⁷ на агрегате порядка 10⁴ даёт абсолютное расхождение около
10⁻³ — то есть **копейки на суммах в тысячи рублей**. Для денежных мер это
неприемлемо, поэтому умолчание — `float64`; `float32` остаётся опцией
загрузки для аналитики, где вдвое меньшая память важнее седьмого знака.

Это не теоретическое соображение: при первой сборке умолчанием был `float32`,
и дифференциальные тесты против оракула сразу показали расхождение ~10⁻⁷,
которого достаточно, чтобы сверка перестала сходиться.

### 10.3 Точность масок и редукций

Маски принимают значения ровно 0 и 1, представимые точно, поэтому селекция не
вносит погрешности вовсе. Матрицы перехода иерархий — тоже 0/1, значит
`ROLLUP` численно эквивалентен прямому суммированию по прообразу.

Для MIN/MAX погрешность отсутствует по другой причине: редукция выбирает
существующее значение, а не вычисляет новое.

## 11. Границы математической модели

Сводка того, что **не** покрывается математикой продукта.

| Что | Почему |
|---|---|
| `MIN` / `MAX` над (+, ·) | Доказано непредставимы (§5.4); выражаются над (max, ·) при неотрицательных мерах |
| `COUNT(DISTINCT)` | Не реализовано. Кандидаты: полукольцо множеств, моноид HyperLogLog-скетчей относительно слияния |
| `ORDER BY`, `LIMIT`, `HAVING` | Операции над результирующей таблицей, а не над матрицами; вне алгебры по природе |
| Объединение, разность, θ-соединения | Не реализованы; соединение возможно лишь по совпадению имён измерений |
| Определитель, обращение, симметрия | Часть теории Соколова для квадратных матриц; для OLAP не требуется, в продукте нет |
| Изоморфизм моделей в общем случае | Верен лишь при условии теоремы 5 (измерения образуют ключ) |
| Соответствие оригиналу Соколова (1972) | Не проверено: книга недоступна. Сверка велась с редакцией определения из статьи |
